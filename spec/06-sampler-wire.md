# The sampler wire — full-class cross-implementation verification

The evaluator ladder's bottom rung, specified and portable: a seeded
reference sampler defined on the WHOLE language (multiplicities,
quiescence, branch-dependent schedules — no class-F restriction),
producing byte-identical traces from Python, OCaml and C++. Two
purposes: (i) the deployed runtime's certified fallback rung — when
the certificate refuses exact and factored evaluation (crowded
scenes), the vehicle downgrades to sampling with deterministic cost;
(ii) the triangle extended to the full Ceptre class — the programs
the compiled wire cannot carry (05-ceptre-lineage.md) are still
three-implementation-verified.

The EXISTING kernel sampler (kernel/sampler.py, Mersenne-Twister
seeded) is unchanged — it anchors pinned tests. The REFERENCE
sampler (kernel/refsample.py) is the portable one; both draw from
the same measure (identical tier/weight semantics), they differ
only in RNG and event order.

## 1. The program artifact = the canonical bytes

The sampled program ships as the stage-38 canonical serialization
(03-canonical-key.md) — it is complete for sampling: stages in
declared order with content-sorted clause lines, links, init stage,
init multiset. C++ consumes exactly this block (no grounder, per
the §8.5 doctrine); OCaml grounds from .llp and canonicalizes;
Python is the generator and referee. `program_key` doubles as the
artifact identity of the sampler rung.

## 2. Canonical event order (normative)

    events = for each stage, in declared order:
                 clauses sorted BYTEWISE by their canonical line
             then all links sorted bytewise by their canonical line

The trace records indices into this list. Two consequences: traces
are PRESENTATION-INVARIANT (a shuffled catalog samples identically),
and identical-content clauses sort adjacent (interchangeable — any
stable choice among equal lines yields the same measure and, with
bytewise sort, the same indices).

## 3. RNG: splitmix64 (normative)

    state := seed (uint64)
    next():  state += 0x9E3779B97F4A7C15
             z := state
             z := (z XOR (z >> 30)) * 0xBF58476D1CE4E5B9
             z := (z XOR (z >> 27)) * 0x94D049BB133111EB
             return z XOR (z >> 31)
    unit():  next() >> 11, times 2^-53   (double in [0,1))

All arithmetic mod 2^64. Pinned vectors (seed 42, first three
unit() draws) live in the parity goldens; the FIPS-style selftest
is `metisc --sample-selftest` and the C++/python equivalents in the
gates.

## 4. One step (normative; mirrors kernel/sampler.py exactly)

    tier 0: candidates = clauses of the active stage, canonical
            order; W = w * phi (phi = falling factorial over consume
            counts x count^n over persist counts, computed in exact
            integer arithmetic; W = double multiply of w by phi);
            keep W > 0
    tier 1: if none, links with pre = active stage, same rule
    tier 2: if none, DONE — the trace ends (remaining horizon is
            the done self-loop; nothing is recorded)

    selection: total = sum of W in candidate order (double,
    left-to-right); threshold = unit() * total; walk candidates in
    order accumulating acc += W; choose the first with
    threshold < acc; if rounding exhausts the list, choose the
    last. UPDATE as in §2.2; links switch the stage.

Determinism note: every double operation (the products, the
left-to-right sum, the threshold multiply) is IEEE-754 binary64 in
a specified order — no reassociation, no FMA (compile the C++ rung
without -ffast-math). Weight doubles round-trip through the wire's
%.17g.

Bindings: the production rung multiplies W by the native
weight-port factor exactly as weight_policy does (tier-0 only);
the parity gates run prior-only (registries are per-implementation
native code, out of the byte-parity contract).

## 5. The parity goldens (sample_goldens.txt)

Generated by cpp/parity/gen_sample_goldens.py from
ocaml/parity/sample_manifest.txt (cases: llp [+ pack], init, steps,
seeds; INCLUDES the out-of-class programs — the love triangle and
kitchen sample here). Per case:

    B <case> <steps> <program_key>  block header (steps: the
                                    case horizon — the (done)
                                    transition can postdate the
                                    last recorded event)
    <canonical program bytes>       verbatim (ends with the i-lines)
    E <n-events>                    canonical event-table size
    R <seed> <k> <idx...>           one line per seeded trace:
                                    recorded event indices
    F <seed> <stage|(done)> <atom:count...>   final state, sorted
    .                               block end

Gate: Python writes it; `metisc --sample` reproduces every R and F
line from the .llp sources; the C++ `sample_run` reproduces them
from the canonical bytes alone. Byte equality, full class.
